# Privacy

Last updated: 2026-09-10

WebAgentMate has no WebAgentMate-operated application server in this release.

- The extension reads a page only after the user requests page reading or starts an Agent task.
- A regular-weight disclosure always visible directly above the sign-in button identifies browser sign-in as a referral entry and explains the commission. It is associated with the button for screen readers. When you click the sign-in button, the authorization request sends WebAgentMate's partner referral code to OrcaRouter so it can attribute registrations made during that flow. Later qualifying purchases by referred users may earn the developers a commission under OrcaRouter's partner program.
- The built-in agent defaults to browser execution: the owning extension page sends task context directly to OrcaRouter. Enabling local files and commands uses the Bridge runtime, which sends task context to OrcaRouter. Codex and Claude use Bridge and their own configured model services. The extension also contacts OrcaRouter for sign-in, connection verification and the model catalog.
- The credential obtained through OrcaRouter browser sign-in is persisted in Chrome local extension storage, restricted to trusted extension contexts. The built-in local runtime receives the key when needed for a run; it does not persist it.
- Interface preferences and the selected conversation are stored in Chrome local extension storage. Conversation messages, drafts, tool inputs/results and model/workspace settings are stored in extension IndexedDB on the current device. There is no cross-device synchronization.
- Conversation export writes a user-requested JSON file containing chat, draft and tool history. It excludes application connection settings and native session IDs; any sensitive material already present in the chat or tool output remains part of the backup. The conversation list no longer provides a backup-import entry.
- Codex history import copies selected native transcript content into extension storage and creates an independent native branch on first send. Skill enable/disable actions update local Codex configuration. MCP form responses are supplied to the selected local MCP service; authorization opens the service's own page on explicit user action.
- Clicking the Bridge download button or the folder control while Bridge is unavailable contacts the public GitHub release API for the matching extension version and downloads the selected project installer through Chrome. GitHub receives ordinary request metadata such as IP address and the requested version/platform. No chat, page content or model credentials are included. Installers run only when the user opens them; they register the native host and include a private Node.js runtime. macOS/Windows installation is per-user; Linux packages install the host system-wide.
- Bridge maintains local SQLite task data and does not open a network port. Codex and Claude also retain their own native session records.
- WebAgentMate does not sell personal information or include analytics/advertising SDKs.
- The unified Agent sends page controls and visible text to the selected model so it can answer directly or choose a constrained browser action. The default **Permissions: Ask** mode requests approval for guarded actions. Choosing **Permissions: Auto** automatically approves these requests within the task; sensitive-target restrictions still apply.
- A screenshot authorized under the selected permission mode is sent to the selected model to interpret the visible page. Chrome requires the `<all_urls>` host permission for this capture capability; the executor limits its tools to HTTP(S) pages. Earlier conversation content may be sent to the same model to generate a continuation summary when its context budget is reached.
- Without Bridge, users can run the built-in browser agent and manage saved conversations and drafts. Local files, commands, Codex and Claude require Bridge; selecting one does not silently switch to browser mode. The initiating panel/tab must remain open during a run; checkpoints are saved locally and interrupted actions are not automatically replayed.
- The Bridge runtime connects to Codex, Claude or the built-in OrcaRouter agent. Authorized file, command and browser tools can supply task-relevant content to the selected model provider. Local execution does not imply offline model inference.

Users can erase the Router key with **Disconnect**, remove an individual conversation's extension history and draft with **Delete**, and erase all extension preferences and conversations by deleting Chrome extension data. Exported files must be deleted separately. Deleting an extension conversation does not delete Codex/Claude transcripts or generated files; those remain in their respective local storage.

Disconnecting removes the local credential; it does not request deletion of OrcaRouter's account or referral records. OrcaRouter manages those records under its own [privacy policy](https://www.orcarouter.ai/privacy.html). For questions about WebAgentMate's data handling, use the project's [support page](https://github.com/wintc23/web-agent-mate/issues).
