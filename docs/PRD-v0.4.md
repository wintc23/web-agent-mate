## 1. 文档目的

本文档定义 WebAgentMate 下一版本的完整产品体验与功能边界，作为视觉设计、交互设计、前端、Chrome 扩展、Bridge、测试和发布验收的共同依据。

v0.4 不是对现有页面进行局部美化，而是重新组织产品结构：产品以一条连续对话流作为唯一主工作区，用户通过自然语言完成提问与网页任务；连接、诊断和执行细节退居支撑层。提问、执行、云端来源和本地 Agent 的关系必须一眼可理解，所有不可用状态必须说明原因并给出下一步操作。

## 2. 产品概述

### 2.1 一句话定义

WebAgentMate 是一个运行在 Chrome 侧边栏中的网页 AI 工作台，帮助用户读取、理解并在明确授权下操作当前网页，同时允许用户在 OrcaRouter 和本机已安装的 Agent CLI 之间自由选择。

### 2.2 核心价值

- 不离开当前网页即可提问、总结、翻译和提取信息。
- 将“聊天回答”和“代为操作”明确分离，降低误操作风险。
- 云端与本地 Agent 使用统一入口，但清楚展示数据去向和运行条件。
- 连接故障可自行诊断，不再用“暂时不可用”掩盖真实问题。
- 高风险动作由用户逐步确认，网页内容不能改变用户授权边界。

### 2.3 产品原则

1. **任务优先**：打开侧栏后首先看到能做什么，而不是技术连接卡片。
2. **对话即界面**：提问、任务执行、状态、批准、失败和结果都发生在同一条消息流中，不为 Agent 另建一套复杂界面。
3. **简洁且不失真**：默认只展示当前任务所需的信息和一个主操作；简洁不能以隐藏失败原因或数据去向为代价。
4. **状态透明**：可用性、数据去向、执行中状态、失败原因必须可见，但仅在相关时出现。
5. **逐级授权**：读取、推理、填写、点击分别采用与风险相匹配的确认机制。
6. **本地优先但不误导**：Bridge、本地存储、本地 Agent 是不同概念，必须分别说明。
7. **渐进披露**：连接配置、诊断详情、完整步骤和开发信息默认折叠，按需展开。
8. **可恢复**：每个失败状态都提供明确恢复动作，例如重试、重新授权、安装 Bridge、修复 CLI。
9. **不暴露任意执行**：扩展不能向 Bridge 传递任意命令或参数。

### 2.4 本轮不可妥协的体验决策

- 主界面只有一个连续对话区和一个固定输入区，不使用 Dashboard 式首页。
- “提问”与“执行”共用输入框；输入框旁只显示当前模式按钮，点击后在说明清楚的弹窗中切换。
- 回车发送，Shift+Enter 换行；中文、日文等输入法确认候选时不得误发送。
- 运行时，发送按钮在原位置切换为“停止”按钮；用户不需要寻找另一个控制区。
- Agent 的计划、进度、批准和结果以对话内消息呈现；详细日志按需展开。
- 顶部设置按钮进入专门的设置页面；设置页包含“设置 / 关于”导航，返回后保留对话、滚动位置和草稿。
- 输入框旁只保留“当前模式”“当前运行位置与模型/Agent”两个选择入口，不放页面上下文或其他悬浮按钮。
- 上下方向键仅在光标位于第一行/最后一行时浏览最近发送记录；离开历史末端时恢复未发送草稿。
- 所有回答与 Agent 的理由/总结必须使用当前界面语言。
- 命中 Orca Free 额度或长度限制时，直接弹出模型选择并解释可切换到付费模型或本地 Agent。

## 3. 背景与现状问题

### 3.1 当前体验问题

- 首屏同时堆叠 Chat、Agent、OrcaRouter 连接、隐私和开发信息，视觉层级混乱。
- 大面积渐变、阴影和卡片相互竞争，缺少稳定的阅读焦点。
- “本地连接”“Bridge”“本地 Agent”“OrcaRouter”概念混在同一页面。
- Agent 不可运行时按钮直接禁用，但用户不知道缺少哪一个条件。
- OrcaRouter “有 Key”“Key 已验证”“API 可调用”没有清楚区分。
- 本地 Agent 没有形成完整的选择、检测、修复和运行体验。
- 所有异步操作共用一个 busy 状态，一个请求会锁住无关区域。
- Agent 仅显示最后结果，缺少任务步骤、待批准动作和失败位置。
- 普通聊天必须先手动读取网页，但界面没有自然引导。
- 错误信息过度归一化，难以区分认证、限流、余额、网络、Bridge、CLI 和页面权限问题。
- 开发信息长期占据主界面，普通用户不需要持续看到回调 URL。

### 3.2 需要解决的核心问题

1. 用户在 5 秒内能否理解“提问”与“执行”的区别？
2. 用户在 10 秒内能否开始第一次网页提问？
3. 当功能不可用时，用户能否知道确切原因并完成修复？
4. 用户能否明确知道当前数据会发送给 OrcaRouter，还是交给本机 CLI？
5. Agent 执行时，用户能否看懂它已经做了什么、下一步准备做什么？

## 4. 目标与非目标

### 4.1 v0.4 产品目标

- 重建清晰、克制、现代、以对话为核心的侧边栏界面。
- 提供完整的新用户引导和首次任务路径。
- 建立统一的模型/Agent 弹窗和专用设置页。
- 支持 OrcaRouter、Codex CLI、Claude Code、Coco CLI 的检测与状态展示。
- 建立嵌入消息流、可按需展开的 Agent 执行步骤与批准流程。
- 建立结构化错误、健康检查和一键复制诊断信息。
- 保留现有页面读取、对话、任务状态持久化与安全限制。
- 所有主要流程支持中文、英文及现有其他语言。

### 4.2 非目标

- 不提供任意 Shell 命令执行界面。
- 不允许 Agent 处理密码、支付、验证码、删除、购买、法律协议和公开发布。
- 不实现多 Agent 并行协作或 Agent 间自动委派。
- 不实现跨设备同步历史记录。
- 不实现网页后台持续监控或未经用户触发的页面读取。
- 不在 v0.4 中建设 WebAgentMate 自有云端代理服务器。
- 不把 Bridge 描述为本地模型；本地 CLI 仍可能调用其各自云端服务。

## 5. 用户与核心场景

### 5.1 目标用户

#### A. 普通网页阅读用户

- 希望快速总结文章、解释概念、翻译页面。
- 不关心模型和技术细节。
- 需要低学习成本和明确隐私提示。

#### B. 重度 AI 工具用户

- 已安装 Codex CLI 或 Claude Code。
- 希望复用本机认证和 Agent 能力。
- 关心实际调用的是哪个 Agent、版本和数据路径。

#### C. 开发者与排障用户

- 需要查看扩展 ID、回调 URL、Bridge 版本、CLI 路径和错误代码。
- 希望复制不包含密钥的诊断报告。

### 5.2 Jobs to Be Done

- 当我阅读一个复杂网页时，我想直接让 AI 总结或解释，以便快速理解内容。
- 当我需要在网页里完成重复操作时，我想让 Agent 给出并执行安全步骤，以便减少机械操作。
- 当云端服务不可用时，我想切换到已安装的本地 Agent，以便继续工作。
- 当某个 Agent 无法选择时，我想立即知道缺什么以及如何修复。
- 当 Agent 准备点击页面时，我想看到目标和原因，以便决定是否批准。

## 6. 版本范围与优先级

### 6.1 P0：发布必需

- 新信息架构与整体视觉系统。
- 单一对话工作区，以及输入框旁的当前模式弹窗入口。
- 独立的“远端/本地”运行位置选择；提问与执行均支持两条路径。
- OrcaRouter 动态模型目录，按免费/付费分组并展示可用价格信息。
- 对话区顶部的页面上下文栏与读取/刷新状态，不遮挡对话或输入区。
- OrcaRouter 完整登录、验证、断开与错误恢复。
- 本地 Agent 列表、检测结果和选择入口。
- 对话内 Agent 步骤、点击批准，以及固定位置的停止任务控制。
- 专门的设置页面，包含连接、外观、对话和关于信息。
- 按功能拆分 loading 状态。
- 空状态、错误状态、离线状态、Chrome 限制页面状态。
- 键盘可达、读屏标签、颜色对比和减少动态效果支持。
- 现有六种语言键值完整，且模型回答语言与界面语言一致。
- 最近 50 条输入记录保存在扩展本地存储中，并支持边界感知的上下键浏览。

### 6.2 P1：建议随 v0.4 发布

- 最近会话列表与继续对话。
- 提问/执行、远端/本地、远端模型和本地 Agent 选择记忆。
- “始终批准低风险填写”会话级偏好；关闭侧栏后失效。
- 一键复制脱敏诊断报告。
- 模型返回路由信息展示，例如实际路由模型。
- 页面内容变化时提示重新读取。

### 6.3 P2：后续版本

- 自定义模型 ID、收藏与搜索筛选。
- 多页面上下文。
- 可配置 Agent 策略模板。
- 会话导入导出。
- 本地模型运行时，例如 Ollama/LM Studio。
- 企业策略和集中管理。

## 7. 信息架构

### 7.1 一级结构

```text
WebAgentMate
├── 对话工作区
│   ├── 页面上下文栏
│   ├── 连续消息流
│   └── Composer
│       ├── 当前模式 → 模式弹窗
│       └── 当前来源 → 模型弹窗
│           ├── 远端 · 免费/付费模型
│           └── 本地 · 已检测 CLI Agent
└── 设置页面
    ├── 设置
    │   ├── OrcaRouter / Bridge / 本地 Agent
    │   ├── 外观与语言
    │   └── 新建对话
    └── 关于
        ├── 版本与隐私
        └── 开发信息
```

### 7.2 全局框架

```text
┌────────────────────────────────────┐
│ WebAgentMate              [状态] [设置] │
├────────────────────────────────────┤
│                                    │
│ 助手：我可以帮你理解或操作当前网页。     │
│                                    │
│ 用户：总结这篇文章                     │
│ 助手：……                             │
│                                    │
│ [网页上下文：当前网页]           [刷新] │
│ ┌──────────────────────────────┐   │
│ │ 给 WebAgentMate 发消息…           │ [↑] │
│ │ [提问⌄] [远端 · Orca Free⌄]      [↑] │
│ └──────────────────────────────┘   │
└────────────────────────────────────┘
```

运行中，右下角发送按钮在原位置切换为停止按钮：

```text
│ │ [执行⌄] [本地 · Codex CLI⌄]      [■] │
```

### 7.3 导航原则

- 主界面不设置 Chat/Agent 一级标签页，避免用户在两套页面与两份草稿之间切换。
- “提问/执行”以当前模式按钮显示，点击打开模式弹窗；切换不清空输入，也不改变当前会话。
- 运行位置与具体模型/Agent 合并为一个当前来源按钮，点击模型弹窗后再选“远端 / 本地”与具体项。
- 顶部使用文字明确的“设置”按钮进入独立设置页面，不使用含义模糊的省略号菜单。
- 顶部常驻控件为产品标识、全局状态和设置按钮。
- 连接状态只显示一个紧凑文字/图标状态；仅在异常时出现可操作说明。
- 页面上下文位于可滚动对话区顶部，和 Composer 分离，绝不覆盖消息记录。
- 开发信息、完整日志、版本和路径不出现在主工作区。

### 7.4 信息密度规则

- 任一静态视图只能有一个视觉主操作；其他操作使用文字按钮、菜单或折叠内容。
- 不使用卡片套卡片；普通内容依靠留白、分隔线和文字层级组织。
- 不重复展示同一状态。例如顶部已显示“本地 Codex”，消息中不重复常驻显示，只有来源变化或查看详情时再呈现。
- 不常驻展示隐私说明、安全规则、Bridge 状态、快捷键说明或开发信息；首次需要、状态变化或用户主动查看时出现。
- 无任务时不显示空的时间线、统计面板、连接卡片或大面积插画。
- Toast 仅用于跨上下文且短暂的结果；任务结果、错误和恢复动作优先留在消息流中。

## 8. 核心体验设计

### 8.1 首次使用

#### 首次打开状态

在空对话中展示一条简洁的助手欢迎消息，不使用全宽欢迎卡片或大面积插画：

- 标题：“从当前网页开始”
- 说明：“你可以提问、总结，或让我执行安全的网页操作。”
- 三个建议 Chip：“总结当前页面”“解释选中内容”“在页面中查找”
- 消息流顶部的页面上下文栏显示“当前网页 · 未读取”，并提供文字明确的读取按钮。
- 若没有可用来源，仅在输入框旁显示“配置 AI”主操作及一句原因。
- 首次读取前保留明确的用户触发动作，不自动读取正文。

#### 首次连接

“配置 AI”进入专用设置页：

- OrcaRouter 卡片：无需安装本地软件，支持提问和执行。
- Codex/Claude/Coco 卡片：需要 Bridge 和对应 CLI；显示检测状态。
- 用户可以先配置任意一个来源，不强制 OrcaRouter。

#### 完成条件

- 至少一个推理来源可用。
- 当前页面已成功读取。
- 用户返回原对话且草稿未丢失。

### 8.2 页面上下文

页面上下文使用消息流顶部的清晰状态栏，展示标题和“读取 / 刷新”操作。它跟随消息流滚动，不固定在输入框上方，也不遮挡历史记录。

状态：

1. **未读取**：显示“尚未读取当前网页”和“读取”按钮。
2. **读取中**：按钮显示加载状态，不锁住设置页。
3. **已读取**：默认显示 favicon、截断后的页面标题和“已读取”；域名、字符数、读取时间、刷新与清除放入展开层。
4. **页面已变化**：显示黄色提示“页面可能已更新”，允许重新读取。
5. **不可读取**：明确说明 Chrome 内部页面、商店页面或权限限制。
6. **空页面**：说明未找到可用正文，并允许继续使用页面标题和可见控件。

隐私行为：

- 未经用户操作不得读取页面正文。
- 切换标签页后旧上下文保留但标记为“来自其他标签页”，不得静默替换。
- 清除上下文后删除内存中的页面正文。

### 8.3 统一对话工作区

所有用户输入、模型回答、Agent 步骤、批准请求、错误与结果都进入同一条按时间排序的消息流。切换“提问/执行”只改变下一条消息的处理方式，不创建另一套界面。

#### 空状态

- 页面未读取：显示读取引导。
- 页面已读取：显示不超过三个建议动作，用户发送首条消息后隐藏。
- 没有可用模型：输入框与草稿保持可见；发送位置显示“配置 AI”，并明确“尚未配置可用来源”。

#### 对话区

- 用户消息右对齐，助手消息左对齐。
- 消息正文支持基础 Markdown、代码块、链接与复制。
- 助手消息默认不显示冗长元数据；悬停、聚焦或展开详情后显示来源，例如“OrcaRouter · 实际模型”或“Claude Code · 2.1.114”。
- 生成中在未完成的助手消息末尾显示低干扰状态；停止按钮固定在输入框发送按钮原位置，不显示全页面 Spinner。
- 失败消息保留在对话流中，可单条重试或切换来源后重试。

#### 输入区

- 自适应高度，最大 6 行。
- Enter 发送，Shift+Enter 换行；输入为空或仅含空白时不发送。
- 输入法处于候选确认阶段时，Enter 只确认候选，不触发发送；实现需检查 composition 状态。
- 运行期间输入框保持可编辑，用户草稿不会丢失；发送位置显示停止按钮，Enter 暂不提交新消息，也不隐式停止当前任务。
- 停止完成后立即恢复发送按钮和输入焦点；草稿仍保留。
- 工具栏只显示两个紧凑按钮：`当前模式` 与 `当前来源 · 模型/Agent`；两者均使用 Ant Design 图标和文字。
- 模式按钮打开弹窗，逐项解释“提问”和“执行”的行为及安全差异。
- 来源按钮打开模型弹窗；弹窗先切换“远端 / 本地”，远端按“免费模型 / 付费模型”分组并显示可用价格，本地展示 Bridge 检测到的 CLI 状态。
- 本地不可用项仍可查看原因，但不能选中。
- 远端默认选中 `orcarouter/free`。目录拉取失败时保留 Free/Auto 回退项，不让连接页或输入区崩溃。
- 运行位置、远端模型和本地 Agent 分别持久化。用户从本地切回远端时恢复上次远端模型，反之亦然。
- 最近 50 条已发送输入本地保存；光标在第一行时 ArrowUp 取更早消息，在最后一行时 ArrowDown 取更新消息，越过最新记录后恢复原草稿。
- 每次请求携带由当前界面语言映射出的 `responseLanguage`，远端提示词与本地 Bridge 提示词均强制使用该语言回答。
- 收到 `PROVIDER_FREE_UNAVAILABLE` 或 `PROVIDER_FREE_PROMPT_LIMIT` 时，失败消息留在对话中，同时自动打开模型弹窗并显示对应额度说明。
- 页面上下文未读取时发送，在消息流末端显示“读取网页后发送”与“取消”，不使用阻断式弹窗。
- “不带网页内容发送”作为 P1 行内选项，不影响 P0 的简洁结构。

### 8.4 对话式 Agent 执行

#### 任务创建

用户在同一个输入框将模式切换为“执行”，输入自然语言目标并发送。界面不再重复展示任务目标输入框、上下文摘要、安全卡片和“开始任务”大按钮。

输入区仅保留：文本输入、当前模式、当前来源与发送/停止。页面上下文位于消息流顶部；安全边界只在首次执行、来源变化或动作被阻止时说明。

模型/Agent 选择器必须展示：

- 名称与图标。
- 云端/本机 CLI 标签。
- 可用、未配置、未安装、认证失效、版本不兼容状态。
- 版本或模型名称。
- 数据去向一句话说明。

入口直接位于 Composer 工具栏，具体选项位于模态弹窗。模型目录按免费/付费分组；本地不可用项可以被查看但不能被选中，设置页面提供连接与修复入口。

#### 执行消息

任务启动后，在对话流中创建一条执行消息。默认只显示当前阶段和最近完成的步骤，完整步骤点击“查看过程”后展开：

```text
助手  正在执行
✓ 已读取页面
✓ 已填写“搜索词”
  正在分析下一步…
  [查看过程]
```

每一步展示：

- 状态：分析中、已完成、待批准、失败、已停止。
- 动作类型：读取、滚动、填写、选择、点击、完成。
- 操作目标的可读标签。
- Agent 给出的原因。
- 执行结果。
- 时间戳。

#### 操作批准

批准请求作为一条可聚焦的行内助手消息出现，避免用户离开对话上下文。消息包含：

- 动作：“点击”
- 目标：“搜索”按钮
- 页面域名
- Agent 原因
- 页面中目标元素的高亮提示
- “批准一次”主按钮
- “拒绝并停止”次按钮

禁止用模糊文案，例如仅显示动作代码 `click`。

只有需要展示大量安全信息或浏览器空间不足时，批准详情才可展开为模态对话框；打开与关闭必须保持焦点可预测，默认焦点不得落在“批准”上。

#### 完成状态

- 显示结果摘要、总步骤数、使用来源和耗时。
- 默认仅显示“继续”主操作；“新建对话”和“复制摘要”进入消息菜单。
- 如果达到步数上限，明确显示“已暂停，等待继续”，不能伪装为完成。

#### 停止语义

- 用户点击停止后，按钮立即进入“正在停止”状态，当前执行消息标记为“正在停止”，且不再接受新的动作。
- 提问模式的流式请求应真正取消；底层不支持取消时，UI 必须忽略迟到内容，不得追加到已停止消息。
- 本地 Agent 任务必须向 Bridge 发送取消意图并终止对应子进程；无法确认终止时显示“停止未确认”，但继续阻断其返回动作。
- 停止完成后保留已生成文本和已完成步骤，消息状态为“已停止”，并提供“继续”或“重试”。
- 停止不能撤销已经完成的网页操作，界面需在停止结果中说明最后一个已执行步骤。

### 8.5 历史记录

- 按今天、昨天、更早分组。
- 以会话为单位保存，同一会话可同时包含提问和 Agent 执行消息。
- 显示标题、网页域名、最近使用模式、更新时间。
- 支持打开、删除和清空。
- 删除为可恢复确认，不使用浏览器原生 alert。
- Bridge 不可用时展示说明，不把历史区显示为空数据。

## 9. 设置页面

### 9.1 设置页结构

设置页由顶部设置按钮进入，并提供“设置 / 关于”两项导航：

- “设置”包含 OrcaRouter、Bridge、本地 Agent、重新检测、外观、语言与新建对话。
- “关于”包含版本、授权协议、本地优先隐私说明和开发回调地址。
- 顶部提供文字明确的返回按钮，返回后保留原对话、滚动位置和草稿。

连接区使用紧凑列表，每个来源一行显示名称、状态和当前主操作，不在主对话界面平铺连接卡片。

### 9.2 OrcaRouter 详情

状态模型：

| 状态 | 展示 | 主操作 |
|---|---|---|
| 未连接 | 未授权 | 使用 OrcaRouter 登录 |
| 授权中 | 等待浏览器授权 | 取消 |
| 有 Key、未验证 | 待验证 | 验证连接 |
| 已验证 | 已连接，可用模型数量 | 重新验证 |
| 凭据拒绝 | 登录已失效 | 重新登录 |
| 限流 | 请求过于频繁，显示恢复建议 | 稍后重试 |
| 余额不足 | 账户额度不足 | 打开 OrcaRouter |
| 网络失败 | 无法连接服务 | 重试 |

展开详情：

- 当前默认路由：`orcarouter/free`，保证新用户在 OrcaRouter 免费限流范围内可直接使用
- 扩展启动时从 `GET /v1/models` 动态读取文本模型；公共目录只用于发现，不能代替 Key 验证
- Composer 将 `orcarouter/free`、零价格模型和 `-free` 模型归入“免费模型”，其他模型归入“付费模型”
- `Orca Auto` 和其他付费模型面向已有余额的用户；选择付费模型不代表免费额度可以抵扣其费用
- 模型选项显示服务端名称；存在 `prompt_per_million` / `completion_per_million` 时显示输入/输出单价
- 429、余额不足、模型不可用与凭据失效必须给出不同的可执行提示
- 最近验证时间
- 授权回调地址仅在高级信息中展示
- 断开连接位于二级危险操作区

### 9.3 Bridge 详情

状态：未安装、连接失败、版本过低、已连接。

展示字段：

- 版本
- 平台
- Native Host 名称
- 最近检测时间

动作：

- 查看安装指南
- 重新检测
- 复制诊断

### 9.4 本地 Agent 列表

每个 Agent 使用一行摘要，状态异常或用户点击时展开：

| 状态 | 条件 | 展示动作 |
|---|---|---|
| 可用 | CLI 存在且健康检查成功 | 设为默认 |
| 未安装 | 找不到可执行文件 | 查看安装方式 |
| 启动失败 | `--version` 非零退出 | 查看错误 |
| 未登录 | CLI 能启动但推理失败 | 打开登录说明 |
| 超时 | 120 秒内未响应 | 重试/查看诊断 |
| 不兼容 | 缺少需要的无头参数 | 更新 CLI |

本地 Agent 数据提示必须写明：

“页面观察数据会传给本机 CLI。CLI 是否继续访问云端，取决于该 CLI 的账户和配置。”

本地路径同时支持提问与执行：提问调用 `chats.complete_local` 返回自然语言；执行调用 `agents.plan_local` 返回受约束动作。两者都必须创建可取消 task，并由 Bridge 终止对应 CLI 子进程。

## 10. 功能需求

### 10.1 全局与导航

- **FR-G01**：顶部必须显示产品名称、全局健康状态和文字明确的设置按钮；设置按钮进入独立设置页面。
- **FR-G02**：全局健康状态分为正常、部分可用、不可用，不得只用红/绿颜色表达。
- **FR-G03**：提问与执行模式共用一个输入框和一份草稿，切换模式不得清空输入。
- **FR-G04**：切换语言后当前界面立即更新。
- **FR-G05**：主题支持系统、浅色、深色，并持久化。
- **FR-G06**：不同功能使用独立 loading 状态。
- **FR-G07**：默认工作区不得展示连接卡片、统计面板、完整执行日志或开发信息。
- **FR-G08**：从设置页返回后，焦点返回设置按钮；对话滚动位置、消息和草稿保持不变。
- **FR-G09**：模式与来源是两个独立入口；来源弹窗内部再选择运行位置和模型/Agent，选择具体项时同步提交对应位置。
- **FR-G10**：设置页必须提供“设置 / 关于”导航，连接、外观、语言、新建对话、版本、隐私和开发信息均有明确归属。

### 10.2 页面读取

- **FR-P01**：仅在用户点击后读取活动标签页。
- **FR-P02**：读取成功后保存标题、URL、正文、选择文本和读取时间。
- **FR-P03**：正文上限与元素上限必须在发送前截断并可诊断。
- **FR-P04**：Chrome 限制页面返回专用错误，不显示通用错误。
- **FR-P05**：页面没有正文时仍允许 Agent 读取可见可交互元素。

### 10.3 对话与输入

- **FR-C01**：支持快捷动作和自由提问。
- **FR-C02**：发送前验证页面上下文和模型来源可用性。
- **FR-C03**：非输入法合成状态下，Enter 发送，Shift+Enter 插入换行；空白内容不发送。
- **FR-C04**：必须监听输入法 composition 状态，中文、日文、韩文候选确认 Enter 不得触发发送。
- **FR-C05**：发送成功后清空已发送内容并保持输入焦点；发送失败时保留原文或提供一键恢复。
- **FR-C06**：运行期间输入框仍可编辑并保存草稿，但禁止提交第二条并发消息；Enter 不产生隐式排队或停止行为。
- **FR-C07**：发送按钮在同一位置切换为有文字可访问名称的停止按钮，触发区域不得缩小或跳动。
- **FR-C08**：支持停止生成；若底层不支持取消，UI 标记“正在停止”并忽略迟到响应。
- **FR-C09**：停止后保留部分回答并标记“已停止”，随后恢复发送能力和输入焦点。
- **FR-C10**：失败消息支持原来源重试和换来源重试。
- **FR-C11**：有 Bridge 时持久化会话；无 Bridge 时本次会话仍可使用。
- **FR-C12**：消息历史发送上限必须明确，默认最近 12 条。
- **FR-C13**：运行状态、停止结果和错误在消息流中呈现，不得用全屏遮罩阻断其他只读操作。
- **FR-C14**：远端与本地均支持提问；本地提问必须通过所选 CLI 返回回答，不得伪装成仅用于执行的入口。
- **FR-C15**：远端模型目录必须动态获取并按免费/付费分组；目录失败时提供 `orcarouter/free` 与 `orcarouter/auto` 的安全回退。
- **FR-C16**：远端模型、本地 Agent 与运行位置分别持久化；重新打开侧栏时恢复有效选择，无效选择回退到首个可用项。
- **FR-C17**：输入历史最多保存最近 50 条；仅在光标位于首行/末行且没有文本选择时拦截 ArrowUp/ArrowDown，越过最新项恢复原草稿。
- **FR-C18**：远端与本地请求都必须携带界面语言，回答、Agent 原因和总结使用该语言。
- **FR-C19**：免费额度或免费上下文限制触发时，保留失败消息并自动弹出模型选择，提供付费模型和本地 Agent 两种恢复路径。

### 10.4 Agent

- **FR-A01**：启动任务必须传递明确的 Agent 来源 ID。
- **FR-A02**：任务存储来源 ID，批准后不得回退到其他来源。
- **FR-A03**：每次规划前重新观察页面，避免使用过时元素。
- **FR-A04**：每个任务最多 12 步；一次连续执行最多 5 步。
- **FR-A05**：点击必须批准；敏感目标在批准前直接阻断。
- **FR-A06**：任务必须支持按 task ID 停止；点击停止后立即阻断后续网页动作和迟到响应。
- **FR-A07**：本地 CLI 仅接受固定适配器参数，不接受来自 UI 的命令字符串。
- **FR-A08**：本地 CLI 120 秒超时，标准输出保留上限 256 KiB，错误输出展示前脱敏截断。
- **FR-A09**：模型输出必须经过动作 schema 校验和当前页面目标校验。
- **FR-A10**：任务失败必须记录失败步骤、错误分类与可重试性。
- **FR-A11**：本地 CLI 停止必须由 Bridge 终止对应子进程并返回确认；UI 不得只做视觉上的“假停止”。
- **FR-A12**：批准请求必须作为对话内消息可被键盘访问；默认焦点不得直接落在批准按钮上。

### 10.5 连接与诊断

- **FR-D01**：OrcaRouter OAuth 端点通过官方 discovery 文档获得，并限制可信 HTTPS 主机。
- **FR-D02**：OAuth Key 验证成功后才能标为已验证。
- **FR-D03**：验证状态和时间存储于 Chrome trusted storage，不依赖 Service Worker 内存。
- **FR-D04**：Bridge 检测返回版本、平台和协议版本。
- **FR-D05**：CLI 检测必须真实运行健康检查，而非仅判断文件存在。
- **FR-D06**：诊断报告包含版本与错误代码，不包含 API Key、Prompt 正文和页面正文。
- **FR-D07**：错误分类至少包括认证、权限、限流、余额、网络、超时、Bridge、CLI、页面、模型输出。
- **FR-D08**：Key 验证必须调用需要认证且不产生推理费用的端点；公开模型目录的 200 响应不得用于证明 Key 有效。

## 11. 状态与错误设计

### 11.1 错误对象

内部统一错误结构：

```ts
interface AppError {
  code: string;
  category: "auth" | "provider" | "bridge" | "cli" | "page" | "agent" | "unknown";
  title: string;
  detail?: string;
  retryable: boolean;
  action?: "retry" | "reconnect" | "install_bridge" | "update_cli" | "open_settings";
  httpStatus?: number;
}
```

### 11.2 用户提示原则

- 标题说明发生了什么，例如“Codex CLI 无法启动”。
- 正文说明原因，例如“当前 Codex 需要 Node.js 18 或更高版本”。
- 主操作说明下一步，例如“重新检测”。
- 高级详情保留错误代码和有限服务端信息。
- API Key、授权码、页面正文和完整 Prompt 必须脱敏。

### 11.3 关键错误映射

| 错误 | 用户文案 | 恢复动作 |
|---|---|---|
| 401/403 | OrcaRouter 登录已失效 | 重新登录 |
| 429 | 请求过于频繁 | 按 Retry-After 重试 |
| 余额不足 | OrcaRouter 额度不足 | 打开账户页面 |
| Bridge 未找到 | 未检测到本地 Bridge | 查看安装指南 |
| Bridge 版本过低 | Bridge 需要更新 | 下载安装新版 |
| CLI 未找到 | 未安装对应 CLI | 查看安装方式 |
| CLI 非零退出 | CLI 启动失败 | 展开错误/重新检测 |
| CLI 超时 | Agent 响应超时 | 重试或换来源 |
| 页面不可访问 | Chrome 不允许读取此页面 | 打开普通网页 |
| 输出格式错误 | Agent 返回了无法执行的动作 | 重试或换来源 |

### 11.4 对话运行状态机

| 状态 | 输入框 | 右侧主控件 | 消息流表现 | 可进入状态 |
|---|---|---|---|---|
| 空闲 `idle` | 可编辑、Enter 可发送 | 发送 | 无运行提示 | 发送中 |
| 发送中 `submitting` | 可编辑但不可再次提交 | 停止 | 已创建用户消息和助手占位 | 运行中、停止中、失败 |
| 运行中 `running` | 可编辑并保留草稿 | 停止 | 流式回答或当前执行步骤 | 待批准、停止中、完成、失败 |
| 待批准 `awaiting_approval` | 可编辑但不可提交 | 停止 | 行内批准消息 | 运行中、停止中 |
| 停止中 `stopping` | 可编辑但不可提交 | 停止中（不可重复触发） | 保留部分结果并显示正在停止 | 已停止、停止未确认 |
| 已停止 `stopped` | 可编辑、Enter 可发送 | 发送 | 标记已停止，提供继续/重试 | 空闲、发送中 |
| 完成 `completed` | 可编辑、Enter 可发送 | 发送 | 显示结果和必要后续操作 | 空闲、发送中 |
| 失败 `failed` | 可编辑、Enter 可发送 | 发送 | 原位显示原因和恢复动作 | 空闲、发送中 |

状态约束：

- 状态改变不得导致输入区位置、宽度或滚动容器突变。
- `submitting`、`running`、`awaiting_approval` 和 `stopping` 共享同一个运行 ID；Service Worker 重启后必须能从持久化记录或 Bridge 查询结果恢复，而不是回到假空闲。
- 每个运行 ID 只能存在一个终态；收到终态后的迟到事件全部丢弃并记录诊断。
- 读屏只宣告有意义的阶段变化，不逐 token 宣告，也不重复播报“正在加载”。

## 12. 视觉设计规范

### 12.1 设计方向

关键词：简洁、清晰、安静、可靠、轻量。

视觉基线是“单一画布上的对话”，不是由许多卡片拼成的控制台：

- 页面画布、对话流、Composer 停靠区和输入表面使用不同明度；助手回答使用轻量边框表面，输入边界无需依赖占位符也能被识别。
- 用户消息使用轻微着色的紧凑气泡，最大宽度为消息区的 85%。
- 输入区固定在底部，但不得遮挡最后一条消息；顶部仅保留一行工具栏。
- 边框只用于输入区、可交互控件和需要明确边界的批准/错误消息。
- 图标服务于识别，不作为装饰；只有图标无法清楚表达时必须配文字或可访问名称。

避免：

- 大面积彩色渐变。
- 卡片套卡片、每个状态一个框、每条助手消息一个重气泡。
- 多个高饱和主按钮同时出现。
- 纯技术状态占据主视觉。
- 用 emoji 代替产品图标。
- 大标题、宣传口号、空状态插画、持续旋转的加载动画。
- 同一层级同时出现超过三个 Chip，或在每条消息下常驻一排操作按钮。

### 12.2 色彩

- 主按钮使用 `brand-action + on-brand`；普通按钮优先使用中性色，只在选中或主操作时出现靛蓝。

- `border-subtle` 只做装饰分隔，不能独自承担输入框、按钮或状态识别。
- 停止按钮默认使用中性表面、主文字和方形停止图标；仅在悬停、聚焦或停止失败时使用错误色，不显示大面积红底。
- 成功、警告、错误必须同时配合文字或图标，不能只改变颜色。
- Agent 与普通回答使用同一色彩体系，通过“提问/执行”文字、图标和消息结构区分。
- 默认跟随系统主题；根节点声明 `color-scheme: light dark`，并在文档头声明 `<meta name="color-scheme" content="light dark">`，使表单、滚动条和初始画布同步主题。
- 颜色必须通过语义变量引用，业务组件中禁止散落硬编码 Hex 值。

### 12.3 字体与层级

- 系统字体优先：Inter / SF Pro / Segoe UI / sans-serif。
- 产品标题：16px / 24px / 650。
- 消息标题：14px / 20px / 600。
- 正文：14px / 22px / 400。
- 辅助信息：12px / 18px / 400。
- 代码与诊断：12px 等宽字体。
- 助手长文本单行宽度不超过 72 个中文字符的视觉等效宽度。

### 12.4 间距与圆角

- 基础间距单位：4px。
- 页面左右边距：16px；窄屏最小 12px。
- 消息组间距：20px；同组内容间距：8px。
- 输入框和按钮视觉高度最低 44px，粗指针设备触发区域最低 48px。
- 用户消息圆角 14px；输入框 14px；标签 999px。
- 阴影仅用于模态浮层和输入区的轻量抬升；主消息区不使用重阴影分层。

### 12.5 动效

- 过渡时间 120–180ms。
- 仅使用透明度、颜色和小范围位移。
- 遵循 `prefers-reduced-motion`。
- 运行状态优先使用静态文字和轻微光标；不使用低频脉冲或持续旋转的大型动画。
- 发送切换为停止时不改变按钮尺寸，不推动周围内容。

## 13. 组件规范

### 13.1 AppHeader

- 单行展示产品名称、GlobalHealth 和带文字的设置按钮。
- 高度保持紧凑，不展示副标题、账户卡片或多行连接说明。
- 设置按钮进入专门页面；不使用省略号或含义依赖猜测的图标按钮。

### 13.2 GlobalHealth

- 三态：正常、部分可用、不可用。
- 仅展示状态，不伪装为按钮；连接操作统一进入设置页。
- tooltip/可访问名称必须包含文字状态。

### 13.3 ConversationStream

- 使用语义化消息列表，保持从旧到新的稳定阅读顺序。
- 自动滚动仅发生在用户原本位于底部时；用户向上阅读时不抢夺位置，改为显示“回到最新”。
- 流式输出不移动键盘焦点，不对每个 token 触发读屏播报。

### 13.4 Composer

- 使用语义化 `<form>`、`<textarea>` 和 `<button type="submit">`；停止操作使用独立的 `<button type="button">`，不用可点击 `div` 模拟控件。
- 包含输入、当前模式按钮、当前来源按钮和发送/停止；页面上下文不放在 Composer 内。
- 发送与停止共用固定槽位和尺寸，但必须拥有不同的可访问名称和图标。
- 输入框有持久的可访问名称；placeholder 只用于示例，不承担标签作用。
- 所有键盘行为遵循 8.3 与 FR-C03～FR-C19。

### 13.5 PageContextBar

- 位于可滚动消息流顶部，不与 Composer 重叠。
- 显示“网页上下文”、截断标题和文字明确的“读取 / 刷新”按钮。
- 默认不展示域名、字符数和读取时间，避免占用主工作区。

### 13.6 ExecutionLocation 与 ModelPicker

- 主界面使用原生按钮打开 `<dialog>`；弹窗使用语义按钮展示选项，不平铺在主工作区。
- `ExecutionLocation` 仅包含“远端”“本地”，与提问/执行模式正交。
- 远端 `ModelPicker` 分为“免费模型”“付费模型”两个视觉分组；模型列表来自 OrcaRouter 实时目录。
- 本地 `ModelPicker` 变为 `AgentPicker`，展示 Codex、Claude、Coco 的实际检测状态。
- 分别记忆运行位置、远端模型和本地 Agent；切换位置后恢复该位置上次的选择。
- 320px 下保留模式、位置和当前模型/Agent 的文字，可截断过长模型名，但不得产生横向滚动。

### 13.7 InlineRun

- 作为助手消息的一种，默认显示当前状态、最近步骤与“查看过程”。
- 展开的步骤使用语义化列表。
- 当前步骤 `aria-current="step"`。
- 仅关键阶段变化通过集中式 `aria-live="polite"` 宣告。
- 失败步骤展开错误详情。

### 13.8 InlineApproval

- 默认作为行内消息实现，包含清楚命名的“批准一次”和“拒绝并停止”按钮。
- 到达批准消息时不得自动聚焦“批准”；读屏礼貌宣告有动作等待确认。
- 详情过多时可使用原生 `<dialog>` 展开；关闭后焦点返回行内批准消息。
- 批准按钮不得只显示“确定”。

### 13.9 ErrorNotice

- 局部错误出现在对应区域，不统一堆到页面顶部。
- 全局错误仅用于 Bridge 整体断开等跨区域问题。
- 同一错误短时间内合并，不连续刷屏。

## 14. 数据与接口要求

### 14.1 Chrome Storage

建议键：

```text
language_preference
theme_preference
ask_provider
act_provider
conversation_draft
active_run
orcarouter_api_key
orcarouter_verified_at
onboarding_completed
```

规则：

- API Key 仅存储于 trusted extension contexts。
- Service Worker 不保存需要跨事件存在的内存状态。
- 草稿、活动运行 ID、运行状态和最近已接收事件序号需要持久化，以承受 Manifest V3 Service Worker 休眠或重启。
- 断开 OrcaRouter 时同步删除 Key 和验证时间。

### 14.2 Bridge 协议

P0 方法：

```text
bridge.hello
bridge.diagnostics
agents.adapters
agents.start
agents.status
agents.plan_local
agents.record_step
agents.cancel
conversations.create/list/get/delete
messages.append
storage.stats
```

`agents.adapters` 返回：

```json
{
  "adapters": [
    {
      "id": "codex",
      "name": "Codex CLI",
      "kind": "local",
      "capabilities": ["chat", "plan", "actions", "cancel"],
      "available": true,
      "version": "0.153.2",
      "status": "ready",
      "detail": "Authenticated"
    }
  ]
}
```

`agents.start` 必须返回稳定的 `run_id`。`agents.cancel` 接受 `run_id`，并返回 `cancelled`、`already_finished` 或 `not_found`；Bridge 收到取消后负责终止对应 CLI 子进程并停止转发其输出。所有运行事件带单调递增的 `sequence`，扩展据此忽略重复、乱序和终态后的迟到事件。

### 14.3 兼容性

- 扩展发现旧 Bridge 时必须显示“版本过低”，不能退化为“未安装”。
- 数据库迁移必须保留既有会话与任务。
- 新字段必须提供默认值。

## 15. 隐私与安全

### 15.1 数据路径披露

- OrcaRouter：页面上下文与 Prompt 从扩展直接发送至 OrcaRouter。
- 本地 CLI：页面观察数据经 Native Messaging 传给本机 CLI；CLI 后续数据处理由其配置决定。
- Bridge：保存本地会话和任务状态，不保存 OrcaRouter Key。

### 15.2 网页内容不可信

- 页面正文只能作为参考数据，不得成为系统指令。
- 页面中的 prompt injection 不得修改用户目标、安全限制或审批要求。
- 模型输出必须经过本地确定性验证后执行。

### 15.3 敏感操作

始终阻断：

- 密码、OTP、CAPTCHA、身份验证秘密。
- 银行卡、CVV、支付和购买。
- 文件上传。
- 删除数据。
- 同意法律协议。
- 发送消息、提交表单、公开发布。

点击默认需要批准；未来放宽必须通过单独安全评审。

## 16. 无障碍与国际化

- 完整键盘导航，焦点顺序与视觉顺序一致。
- 所有按钮优先使用原生 `<button>`，输入区使用有可访问名称的 `<textarea>`，不得用 `div` 模拟基础控件。
- Enter、Shift+Enter、Tab、Shift+Tab、Space 和 Escape 的组合测试必须覆盖；输入法 composition 期间的 Enter 单独测试。
- `:focus-visible` 始终清楚可见，任何交互元素都不得使用正数 `tabindex`。
- 所有仅图标按钮提供本地化 `aria-label`。
- 不用颜色作为唯一状态标识。
- 模态框关闭后焦点返回触发元素。
- 页面只保留一个 `polite` 和一个 `assertive` 宣告区域；运行阶段使用 polite，关键失败使用 assertive，流式 token 不逐字宣告。
- 停止按钮必须被读作“停止生成”或“停止任务”，不能只读作“方块按钮”。
- 支持 200% 页面缩放和 320px 宽度。
- 文案布局需允许德语等长文本扩展 30%。
- 所有新增键必须覆盖 en、zh_CN、zh_TW、pt_BR、ja、de。

## 17. 非功能需求

### 17.1 性能

- 侧栏首次可交互时间目标：本地开发环境小于 1.5 秒。
- 首屏不等待 Bridge 或 OrcaRouter 检测完成；状态异步更新。
- UI bundle 应拆分，首屏压缩体积目标低于 180 KiB。
- 页面读取不得长时间阻塞页面主线程。

### 17.2 稳定性

- 所有网络请求有超时和取消行为。
- Native Messaging 短请求默认 3 秒，CLI 规划请求最长 120 秒。
- Service Worker 重启后连接和活动运行状态可恢复；不得因内存变量丢失而把运行中的任务显示为空闲。
- 取消请求必须幂等；连续点击、重复消息和 Bridge 迟到响应不得恢复已停止任务。
- 重复点击主操作不会创建重复任务。

### 17.3 浏览器支持

- Chrome Stable 当前版本及前两个主版本。
- Manifest V3。
- 不承诺 Firefox/Safari 支持。

## 18. 指标

默认不上传分析数据。开发与可用性验证阶段使用本地匿名计数或人工测试。

核心指标定义：

- 首次成功：安装后 5 分钟内完成一次有效提问或执行任务。
- 页面读取成功率。
- OrcaRouter 授权完成率。
- Bridge 检测成功率。
- CLI 检测到可用后的首次任务成功率。
- Agent 动作批准率与拒绝率。
- 用户主动停止成功率，以及从点击停止到 UI 进入“已停止”的耗时。
- Enter 发送失败率与重复发送率。
- 可恢复错误在一次修复动作后的恢复率。
- 从打开侧栏到首次发送的中位时间。

任何未来遥测必须先更新隐私政策并提供明确开关。

| Orca 限流 | 任意 | 429 | 任意 | 提示稍后重试或换来源 |
| Chrome 内部页 | 任意 | 任意 | 任意 | 提示无法读取该页面 |
| 中文输入法确认候选 | 任意 | 可用 | 任意 | Enter 只确认候选，不发送消息 |
| 输入历史浏览 | 任意 | 可用 | 任意 | 首行 Up / 末行 Down 浏览历史，越过最新项恢复草稿 |
| 中文界面回答 | 任意 | 可用 | 任意 | 远端与本地均携带 `zh-CN` 并以简体中文回答 |
| 云端回答中停止 | 任意 | 可用 | 无 | 部分回答标记已停止，迟到 token 被忽略 |

## 22. 风险与缓解

| 风险 | 影响 | 缓解方式 |
|---|---|---|
| 不同 CLI 参数随版本变化 | 本地 Agent 失效 | 维护最低版本和能力探测，不只检测版本号 |
| Native Messaging PATH 与终端不同 | 找不到 CLI | 搜索可信常见路径，并在诊断中显示实际路径 |
| Service Worker 休眠 | 状态丢失 | 持久状态进入 Chrome Storage |
| 页面 prompt injection | 越权操作 | 系统提示隔离 + 本地 schema/目标/敏感校验 |
| 侧栏宽度有限 | 信息拥挤 | 渐进披露、专用设置页、单主操作原则 |
| 多语言文本膨胀 | 布局破坏 | 30% 文案扩展测试 |
| OrcaRouter 服务或账户问题 | 云端路径不可用 | 明确错误并允许切换本地 Agent |
| 发送、停止和迟到响应竞态 | 重复消息或停止后继续执行 | 每次运行使用唯一 ID、事件序号、幂等取消和单一终态 |

## 23. 待确认产品决策

## 24. Definition of Done

v0.4 只有在以下条件全部满足时才视为完成：

- P0 功能全部通过验收标准。
- 新界面只有一个对话工作区，不再把 Chat/Agent 分成一级页面，也不把连接卡片作为主任务首屏。
- Enter、输入法、流式停止、本地 Agent 停止和 Service Worker 重启恢复均通过自动化与真实 Chrome 测试。
- 用户能从不可用状态直接进入正确修复路径。
- OrcaRouter、Codex、Claude 三条真实链路至少各完成一次端到端任务。
- Coco 若没有确定的官方无头协议，必须明确标记为实验性或移出发布范围，不能伪装为已支持。
- 所有安全阻断和点击批准测试通过。
- Chrome Web Store 文案、隐私政策和截图与实际产品一致。
